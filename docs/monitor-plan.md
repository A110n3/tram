# Tram - 固定区域实时监控翻译（实时字幕）方案

> 状态：**已定稿，待实施**（2026-08-20 讨论定案）。
>
> 实施顺序：`ocr_ndarray` -> `RegionMonitor`（先跑通循环+日志验证漏斗有效性）-> `MonitorWindow` -> 托盘/热键接线 -> 设置项。

## 一、需求

框选屏幕上一块固定区域（游戏/视频字幕位置），持续监控该区域文字变化，自动 OCR 并翻译，实时显示——即"实时字幕翻译"。

## 二、已定技术决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| OCR 引擎 | **RapidOCR（已完成迁移）** | PaddleOCR 已移除（见 ocr-plan.md），进程内 ONNX 推理，模型随包内置离线可用 |
| UI 框架 | **保留 PyQt6，不换 tkinter** | 换 tkinter 仅省约 20% 体积（OCR 栈 ~100MB 省不掉），但托盘、半透明浮窗、点击穿透、全屏框选、高 DPI 全是短板，重写成本远大于收益 |
| 应用瘦身 | 打包侧优化 | ① opencv 换 headless；② spec 排除无用 Qt 插件（qicns/tga 等）；③ 可选 UPX（个别杀软误报）。当前 exe 145MB |
| 变化检测 | **帧差法 + OCR 文本比对**（放弃整体图像 hash） | 视频字幕背景动态变化，hash 永远不相等；帧差做廉价门控，OCR+文本比对做准确判断 |

## 三、核心流水线（漏斗：便宜的先跑）

```
每 500ms（可配置 0.5/1/2s）后台线程循环：
  ① 截图 mss/PIL（后台线程，不碰 GUI 线程）        ~5ms
  ② 帧差 vs 参考帧（cv2 降采样 absdiff）            ~2ms   相似 -> skip
  ③ OpenCV 轻量预处理（灰度/对比度/自动反转/放大）   ~1ms
  ④ RapidOCR 识别                                   50~300ms
  ⑤ 置信度过滤（<0.6 丢弃）
  ⑥ 文本归一化 + 相似度查重（vs 最近 N 条，阈值~0.9）        相似 -> skip
  ⑦ 防抖：连续 2 个周期文本稳定才触发
  ⑧ 提交翻译（丢旧保新）-> 更新监控窗口
```

关键细节：

- **帧差比对参考帧而非相邻帧**：维护"上次翻译成功时的帧"，可扛噪点抖动/抗锯齿微变；动态背景视频下帧差失效属预期行为，此时退化为每周期 OCR。
- **预处理保守**：RapidOCR 检测模型基于自然图像训练，激进二值化（OTSU）会伤识别率，只做灰度、对比度、亮度自适应反转、小区域放大。
- **查重比对历史而非仅上一条**：应对字幕 A->B->A 交替闪回（保留最近 N 条已翻译文本）。
- **归一化**：去空白、全半角统一、去标点后再比较（difflib.SequenceMatcher，阈值 0.85~0.9）。
- **防抖（debounce）**：字幕渐入渐出动画中途 OCR 会读到半截文字，要求连续 2 个周期文本稳定才触发翻译。

## 四、翻译节流：丢旧保新

监控期间同一时刻只允许一个翻译请求在途；新文本到来时若上一个未完成，取消旧任务、提交新文本。用户只关心最新字幕，中间态无价值。

## 五、UI：独立监控小窗

- 新建 `MonitorWindow` 置顶小窗，不复用划词浮窗
- 显示最新译文（突出）+ 最近几条历史（可滚动）
- 可拖动、可关闭；关闭即停止监控
- 控制入口：托盘菜单"开始监控/停止监控" + 热键

## 六、模块划分

```
app/core/monitor.py       新增 RegionMonitor：截图线程 + 帧差 + 防抖 + 查重
app/ui/monitor_window.py  新增 MonitorWindow：独立置顶小窗
app/core/ocr.py           增加 ocr_ndarray()（cv2 路径，脱离 Qt 依赖）
app/ui/region_overlay.py  复用：拖拽框选区域
app/ui/main_window.py     接线：托盘菜单 + 热键启停监控
翻译管道 / TranslateWorker  复用现有实现
```

## 七、新增配置项

- 监控间隔（0.5s / 1s / 2s，默认 0.5s）
- 帧差灵敏度阈值
- 文本相似度阈值
- 历史条数（小窗保留最近 N 条）
- 监控启停热键
